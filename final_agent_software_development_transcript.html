阶段十：HTTP 模式卡点与 Stream 模式选择

我把消息接收模式改成 HTTP 模式，填了 ngrok 地址，但是发布一直提示“消息接收地址校验失败”。浏览器打开回调地址能看到 dingtalk webhook ok，ngrok 也显示 200 OK。

这说明公网地址是通的，不是 ngrok 坏了。问题在于钉钉 HTTP 模式不是普通返回 dingtalk webhook ok 就能通过，它需要加密校验和特定响应格式。你已经完成了：

本地网页 ✅
DeepSeek AI 识别 ✅
ngrok 公网地址 ✅
钉钉能访问 /webhook/dingtalk ✅
钉钉 HTTP 加密校验 ❌

我找不到 token、aes_key、owner_key 怎么办？

找不到不是你眼瞎。钉钉 HTTP 模式确实复杂，可能藏在事件订阅或加密配置里。更现实的做法是改用钉钉推荐的 Stream 模式。Stream 模式不需要公网回调地址，可以绕开 ngrok、HTTPS 证书和 HTTP 加密校验。

钉钉机器人：Stream 模式
Node 项目：运行 Stream 连接脚本
收到钉钉消息 → 调用 DeepSeek → 写入 data/homeworks.json → 网页显示

下一步可以让 Codex 新增 dingtalk-stream.js：

1. 保留 /webhook/dingtalk 作为本地测试接口
2. 新增 dingtalk-stream.js
3. 从 .env 读取 DINGTALK_CLIENT_ID 和 DINGTALK_CLIENT_SECRET
4. 收到钉钉消息后提取文本
5. 调用 callAIParser(messageText, "dingtalk")
6. 保存到 data/homeworks.json
7. package.json 增加 "dingtalk": "node dingtalk-stream.js"

但要注意：你现在用 data/homeworks.json 保存数据，部署到云平台后，免费服务的本地文件不适合长期稳定保存。第一版可以作为功能演示，后续再升级数据库。
